# map-point Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Statamic 6 control-panel fieldtype that stores a geographic coordinate, offering three editor modes — a Google place search, a Google-geocoded map picker, and an OpenStreetMap-geocoded map picker — with no Google JavaScript in the browser.

**Architecture:** A `GeoPoint` fieldtype normalises and validates `{lat, lng}` in PHP. Google is reached only through two authenticated CP routes backed by a one-method `Geocoder` interface with Google and Nominatim implementations; the controller falls back from the first to the second on any failure. One Vue component branches on `config.mode`: a search-only branch and a shared Leaflet map branch whose only mode difference is which geocoder the search box queries.

**Tech Stack:** PHP 8 / Statamic 6 (`statamic/cms ^6.0`), Vue 3 via `@statamic/cms`, Leaflet 1.9.4, Vite, Pest 4 + Orchestra Testbench.

**Spec:** `docs/superpowers/specs/2026-10-22-map-point-design.md`

## Global Constraints

- No Google JavaScript reaches the browser: no `maps.googleapis.com/maps/api/js`, no Google npm package, no Google script tag. Google HTTP APIs are called only from PHP.
- The API key lives in `GOOGLE_MAPS_API_KEY` (`.env`), read via `config/map-point.php`. It never appears in `preload()` output, in a route response, or in the built JS.
- Leaflet pinned to exactly `1.9.4` as an npm dependency; its CSS is bundled, never from a CDN.
- PSR-4 `Estouai\MapPoint\` → `src`, `Estouai\MapPoint\Tests\` → `tests`. Composer licence `proprietary`.
- Default map centre is Portugal: latitude `39.5`, longitude `-8.0`, zoom `6`.
- Default tiles `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png` with an OSM attribution string.
- Nominatim requests send a descriptive `User-Agent` and debounce at least 1000ms; Google search debounces 400ms.
- Tests are PHPUnit-style classes extending `Statamic\Testing\AddonTestCase` (matching the sibling `cookie-consent` addon), run by Pest. No test touches the network.
- `composer test` and `composer lint` both pass at every commit.

## Review Focus

- A coordinate of exactly `0, 0` is valid (Null Island is a real point) and must not be mistaken for an empty value by any truthiness check in `process()`, `preProcessValidatable()`, or the Vue component.
- Latitude and longitude at the exact bounds — `-90`, `90`, `-180`, `180` — are valid and must be stored, not rejected as out of range.
- A search query that is empty, whitespace-only, or over-long must not reach the geocoder as an HTTP request; the route returns an empty result set.
- A Google response that is HTTP 200 but carries an error status (`REQUEST_DENIED`, `OVER_QUERY_LIMIT`, `ZERO_RESULTS`) must trigger the Nominatim fallback rather than being read as success.
- A stored value whose `lat`/`lng` are valid but which carries unexpected extra keys must round-trip without those keys leaking into the augmented output.

`protected $categories = ['special'];`

- [ ] **Step 3: Implement the routes and controller**

`routes/cp.php` declares both GET routes with a `throttle` middleware — every editor keystroke is a billable Google request, so the limit is a cost control as much as an abuse control.

`GeocodeController::search()` validates `q` as a required string with a max length, trims it, and returns an empty result set for a blank query without calling any geocoder. When `provider` is `google` and a key is configured, it tries `GooglePlaces` inside a `try`/`catch (\RuntimeException)`; on failure, or when no key is configured, it uses `Nominatim` and sets `fallback` to `true`.

`details()` requires Google; with no key it returns HTTP 503, since Nominatim has no place-ID concept.

This task has no automated test — the suite is PHP-only and adding a JS test runner for one component is not worth the dependency. Step 5 is a manual verification in a real control panel.

- [ ] **Step 1: Register the component**

`resources/js/cp.js`:

```js
import { Statamic } from '@statamic/cms';
import GeoPoint from './components/GeoPoint.vue';

Statamic.booting(() => {
    Statamic.component('geo-point-fieldtype', GeoPoint);
});
```

- [ ] **Step 2: Build the component shell**

Use the v6 fieldtype stub: `defineEmits(Fieldtype.emits)`, `defineProps(Fieldtype.props)`, `const { expose, update, isReadOnly } = Fieldtype.use(emit, props)`, `defineExpose(expose)`. Branch the template on `props.config.mode`: the `google_poi` branch renders search-only, the other two render the shared map.

Honour `isReadOnly` in every branch — no map clicks, no dragging, disabled inputs, hidden Clear button.

- [ ] **Step 3: Implement the search branch (`google_poi`)**

A text input with a results dropdown. Debounce 400ms, call the search route with `provider=google`, show each row's name and address. Choosing a row with a `place_id` calls the details route and writes the full value — coordinates plus `place_id`, `formatted_address`, and `name`. A response with `fallback: true` shows an inline notice that Google is unavailable and results come from OpenStreetMap.

- [ ] **Step 4: Implement the map branch (`google_map`, `leaflet_map`)**

Import Leaflet and its CSS (`import 'leaflet/dist/leaflet.css'`) so nothing loads from a CDN.

- Instantiate the map in `onMounted` and call `map.remove()` in `onUnmounted` — fields mount and unmount repeatedly inside Replicator and Bard sets, and a leaked map instance keeps running.
- Centre on the stored value, else on the configured default centre and zoom.
- Clicking places or moves the marker; the marker is draggable; both write the value.
- A search box above the map only *centres* it — it never writes the value, so the editor confirms with a click. It calls the search route with `provider=google` for `google_map` and `provider=nominatim` for `leaflet_map`, debouncing 400ms and 1000ms respectively (Nominatim's usage policy caps the rate).
- Two numeric inputs below show the current pair; a valid pair moves the marker. These are what keep the field usable when tiles fail to load — do not disable or hide them on a tile error.
- A Clear button sets the value to `null`.
- A failed search shows an inline message and leaves the map untouched.

Note for the implementer: `0` is a valid coordinate. Guard every "is there a value?" check with an explicit null/`Number.isFinite` test, never `if (lat)`.
